The architecture is the compression: 40 of 48 layers are sliding-window (KV capped at a 1024-token ring, flat forever); the 8 global layers carry a single unified K=V head at 8 KiB/token. Total KV at 32K ≈ 0.6 GB, at 256K ≈ 2.4 GB — which is why weight quantization, not KV quantization, is the memory story.

03

The moat — the SDPA head-dim gap

provable from MLX 0.32 dispatch source

Gemma 4's head dimensions (256 local, 512 global) miss MLX's fused attention kernels entirely. That gap — not a hunch — is what a bespoke kernel program (K1/K2) closes. Everything else is inherited from mature MLX.

MLX 0.32 fused pathSupported head_dimGemma 4 local · 256Gemma 4 global · 512
Full / flash (prefill, q>8)64, 80, 128falls backfalls back

→ Every prefill layer and all global-layer decode/verify run unfused today (the source of Helios's 16K memory blowup and decode tails). K1 = global attention kernel (hd 512, single K=V read, covers q_len 1..γ). K2 = windowed-flash prefill (banded hd 256 local + hd 512 global). K3 = NAX/TensorOps probe — stock-first: Apple's M5 gives ~3.5–4× prefill, ~1.2× decode, so custom GEMM only earns its place if it beats stock.

04

Shape

Rust · owns policy

axum dual API (OpenAI + Anthropic), real SSE, tool-call parser + constrained-JSON, sampler, tokenizer + Gemma template, governor policy, conversation cache, bench/eval

Native C++ / MLX · owns compute

one compiled, shape-bucketed step machine; heterogeneous KV (local ring / global K=V); K1/K2 kernels; softcap epilogue; governor mechanics — narrow C ABI, no Python on the request path

The execution-model ruling (decided up front — Helios's hardest-won lesson)

No define-by-run re-trace, no concatenate-grow KV, no per-step reset_peak, no deferred global-first eval — those four choices produced decode tails of p99 511–2162 ms against a p50 82 ms. hyperion rules the opposite: bucketed compiled steps, in-place slice_update, one engine thread owning explicit MLX streams.

07

Risks the design refuses to repeat

  • Fixture-milestone theater. Helios shipped M06–M11 on stubs; substance was redone. Every gate names tensor-level evidence.
  • The MTP marathon. ~80 goal contracts chasing a +25% gate that stalled at +19.97%. MTP is sequenced late, capped at 2 A/B rounds; opt-in park is a valid outcome.
  • Ported-not-derived governor constants. Bonsai's Qwen ×6 fudge would mispredict on Gemma's KV shape. Constants derived from geometry, calibrated per machine.
  • Near-miss prefix reuse. A numerically-attractive 81% TTFT win was rejected for changing one transcript. Reuse is exact-prefix, bitwise-gated only.
  • Exactness overclaim (NunSpark, v0.2). "MTP-on == MTP-off byte-identical" is unachievable — fp16 pass-shape flips a near-tie ~1/110 tokens. Gate is target-verified + a near-tie counter, not byte-identity.
  • Governor sizing to the ceiling (NunSpark, v0.2). More resident memory isn't faster — past the macOS-compressor cliff throughput collapses. Target the measured optimum, below the OOM ceiling.
